## 三、七个部署缺陷的根因与修复

七个 issue 有一个共同特征：**每一个都不是"配置写错了"，而是"某个环节静默失败，而且失败得很像成功"**。这是本轮最有价值的发现模式。

### 3.1 #212 锁文件把 899 个 URL 钉在内网镜像

`package-lock.json` 里 899 个 `resolved` 全部指向 `registry.npmmirror.com`。

**关键认知**：`npm ci` 会**精确拉取锁文件里记录的 URL**，`--registry` 参数对 lockfileVersion 3 无效；而 `npm ci --package-lock-only` 在锁文件"看起来是最新的"时会打印 "up to date" 并退出 0，**根本不会改写 host**。所以换源只能显式改文件，不能靠重新生成。

修复：全部 `resolved` 改为 `registry.npmjs.org`，`.npmrc` 指定官方源，镜像加速降级为每台机器的个人设置。由 `tests/lockfile-registry.test.ts` 守住。

### 3.2 #213 三处 Node 版本声明互相矛盾

`Dockerfile` 钉 `node:20-slim`，但依赖树里 `@fastify/secure-session → @fastify/cookie → cookie@2` 声明 `engines.node: >=22`。代码一直运行在一个自己声明不支持的运行时上。

修复：镜像升到 `node:22-slim`，`engines` 和 `.nvmrc` 同步为 22——**升镜像而不是降依赖**，因为问题在于声明与实际不符。同时把 `@fastify/cookie` 覆盖到 `11.1.0`（`cookie@1` 的最后一版），把 `cookie` 去重成单一条目。由 `tests/docker-engine-consistency.test.ts` 解析三处 + 锁文件守住。

### 3.3 #214 compose 吃掉 bcrypt hash 里的 `$`

**这是最隐蔽的一个。** `docker compose` 的 `env_file` 会做变量插值，`$2b$12$...` 到达容器时变成 `$2b$12`，于是管理员用正确密码永远登录不上，日志里只有一句 401，没有任何线索指向 `$`。

修复两条：compose 里每个 `$` 必须写成 `$$`；`admin-auth.ts` 对格式非法的哈希返回 **500 + 明确消息**，而不是伪装成密码错误。注意 `docker run -e` **不做插值**，所以两条路径需要同一哈希的不同字面量。

### 3.4 #215 数据库端口暴露到 0.0.0.0

`5432:5432` 既会撞上宿主机已有的 PostgreSQL（起不来），又把数据库暴露到局域网；默认口令还是 `change-me-in-env`。

修复：postgres 端口不再发布（应用走内部 `postgres:5432`），口令改为 `${POSTGRES_PASSWORD:?…}` 强制必填。

### 3.5 #216 导出报告随容器重建丢失

`REPORTS_DIR` 没有持久卷。改 bind mount 又会撞上 uid 1000 vs 1001 的 `nodejs` 属主陷阱。

修复：`REPORTS_DIR=/app/reports` 挂 `reports_data` 命名卷；备份脚本覆盖**两个**卷（数据库 + 报告）。

### 3.6 #217 中文字体是 LFS 指针

`assets/fonts/*.otf` 是 Git LFS 对象。任何没跑 `git lfs pull` 的检出（CI 缺 `lfs: true`、`git archive`、脚本化检出）拿到的是 **133 字节的指针**——它能通过所有"文件是否存在"的检查。

修复：`scripts/verify-font-asset.mjs` 校验**字节内容**（LFS 魔数、OpenType/TrueType 魔数、体积下限），且**两个构建阶段都跑**（真正 ship 的是 runner 阶段）。字体缺失的日志级别从 `warn` 提到 `error`——每一份导出 PDF 都会丢中文，这不是警告。

### 3.7 #218 健康检查在凭据缺失时报告 healthy

`/health` 的 `degraded` 返回 **HTTP 200**，compose healthcheck 只看 `r.ok`，于是**没有任何 LLM 密钥的部署显示为健康**。

修复：区分两个探针——
- `/health` = **存活探针**（`degraded` 也 200，`503` 仅当数据库不可用）
- `/health/ready` = **就绪探针**（一切正常才 200）

所有等待"部署可用"的场景（compose healthcheck、Dockerfile `HEALTHCHECK`、编排器）都必须轮询 `/health/ready`；两者都要**解析响应体**，因为只看状态码正是这个 bug 的成因。`start_period` 设为 60s，因为首次就绪探测要等 30s 的 LLM 超时。

## 四、两件顺带完成的事

### 4.1 #211 密钥扫描从"只告警"变成"真拦截"

CI 里那条扫描全历史的步骤带着 `continue-on-error: true`——因为历史里有 11 条已知命中且无法删除（提交已推送、已克隆）。代价比它避免的噪音更糟：**任何新的泄露也永远无法让构建失败**。

修复：11 条已知命中逐条写入 `.secrets-history-baseline.json`（指纹 + 人工撰写的理由），清单之外一律 exit 1。三条性质防止基线退化成万能豁免：

1. **匹配不到任何东西的条目本身算失败**，否则基线会悄悄接纳"替换掉旧命中"的新东西
2. **按 rule + file + line 匹配**，同一历史文件的另一行出现新密钥照样拦截
3. **不存密钥明文**（指纹 = `sha256(rule + NUL + file + NUL + line)`），否则基线本身就成了公开仓库里的第二份泄露

写测试时发现一个**真实漏洞**：测试用的临时目录不是 git 仓库，而 `gitleaks git` 在那里**退出 0 且报告为空**——脚本一直在对"从未读取的历史"宣布"history is clean"。已加第三道防线：`git rev-list --all --count` 为 0 时 exit 2。现在三种"没有证据"的情况全部退出 2，绝不退出 0。

**历史中的凭据处理结论**：不重写历史。字符串在每个已有克隆和 GitHub 对象缓存里都可读，重写撤不回；**撤销凭据是唯一能终止暴露的动作**。这些凭据属于虚拟/测试组织，两个云 key 已吊销，因此是"已死的字符串"而非活跃泄露。

### 4.2 #210 镜像瘦身（本轮发版一并带出）

`scripts/prune-runtime-deps.mjs`：`node_modules` 731 MB → 163 MB，镜像 1.22 GB → 574 MB。`npm prune --omit=dev` 做不到，因为 `prisma`/`typescript` 既是 devDependencies 又是 `@prisma/client` 的 optional peerDependencies。两个后果：容器内不再有 Prisma CLI（改用 `scripts/migrate-deploy.mjs` 直接用 `pg` 跑 SQL，写 Prisma 格式的 `_prisma_migrations`）；基础镜像是 **Debian slim 而非 Alpine**（`sodium-native` 没有 musl 预编译）。

## 九、本轮的方法论收获

**七个部署 bug 是同一个模式的不同实例：失败伪装成成功。**

- 锁文件换源失败 → 打印 "up to date" 并退出 0
- 镜像缺字体 → 所有"文件存在"检查通过（133 字节指针）
- 健康检查缺凭据 → HTTP 200 + `healthy`
- bcrypt 哈希被吃 → 401，看不出与 `$` 有关
- 密钥扫描漏报 → 步骤 `continue-on-error`，永远绿
- 变异测试失效 → 报 `0.0%`，看起来像测试质量问题
- 密钥扫描读不到历史 → 宣布 "history is clean"

这也是为什么本轮在修复之外，**每一处都补了会失败的测试**（`docker-compose-deployment`、`docker-engine-consistency`、`lockfile-registry`、`health-readiness`、`scan-git-history-secrets`）。一个不会失败的检查，和一个坏掉的检查，在 CI 上是同一个东西。

**"没有证据"绝不等于"通过"**——这条原则现在明确写在扫描脚本的退出码设计里（三种情况全部 exit 2，绝不 exit 0）。
