## 第一组 · 对话引擎（核心心脏）

### 1. `src/core/graph.ts` — 86 行

**职责**：对话引擎入口，`runInterviewGraph()` 是整个访谈流程的唯一调度点。

**看点**：
- 按访谈状态分流：`PENDING` 走 planning 节点（生成首问）；`ACTIVE / WAITING / PROCESSING` 且有用户输入时走 interviewing 节点；
- 访谈完结时不阻塞主流程——通过 `setImmediate` 异步触发分析任务（fire-and-forget 模式，用户最后一条消息的响应不受分析耗时影响）；
- 约 87 行入口完成了"图框架"的职责，是"不为用框架而用框架"工程判断的直接体现。

### 2. `src/core/nodes/interviewing.ts` — 204 行

**职责**：对话主节点，负责一轮完整问答的处理与状态推进。

**看点**：
- `routeAction()` 五条路由规则——LLM 拥有追问"建议权"，规则引擎保留"否决权"：
  - Rule 1：追问已达上限 → **强制推进下一题**（防无限追问）
  - Rule 2：用户要求结束 → 直接完结
  - Rule 3：LLM 判定 FOLLOWUP → 追问计数 +1
  - Rule 4：停留类响应同样计数（**防无进展死循环**）
  - Rule 5：NEXT → 推进下一题，已是最后一题则完结
- `buildFallbackResponse()` 降级响应——LLM 失败时访谈自动降级推进，永不卡死。

### 3. `src/core/nodes/planning.ts` — 39 行

**职责**：访谈启动节点，生成第一条问题。

**看点**：
- 首问润色：让开场问题自然、有温度；
- **意图信号检测**：当问题前 40 字符内缺少意图说明时，自动前置一句访谈目的声明——避免受访者收到"没头没尾"的提问。

### 4. `src/core/types/index.ts` — 103 行

**职责**：访谈状态的 zod schema 定义（全系统的状态契约）。

**看点**：
- 6 种访谈状态枚举（PENDING / ACTIVE / PROCESSING / WAITING / COMPLETED / CANCELLED）；
- 乐观锁双字段设计：`version`（当前版本）+ `originalVersion`（加载时版本）；
- `DEFAULT_MAX_FOLLOWUPS = 5`——每题追问上限的全局默认值；
- 待处理消息/响应队列字段——支撑"消息先接收、后处理"的异步解耦。

## 第二组 · 智能追问与提示词工程

### 5. `src/services/followup.service.ts` — 229 行

**职责**：LLM 追问决策服务——`generateSmartResponse()` 决定"如何回应受访者"。

**看点**：
- **结构化决策输出**：LLM 返回 JSON（thinking / strategy / action / response），程序只执行 action，不解析自然语言；
- **10 个模板变量**注入对话上下文（对话历史 / 当前问题 / 进度 / 已追问次数 / 用户回答等）；
- **注入防护**：所有变量替换对 `{{` 做转义，防止受访者输入构造提示词注入；
- **上下文窗口**：注入最近 6 条对话历史；
- **超限强制**：追问次数到达上限时不依赖模型自觉，程序强制切换推进动作；
- **失败降级**：LLM 异常时返回预置降级话术。

### 6. `src/services/prompt.service.ts` — 231 行

**职责**：提示词模板中心（Prompt-as-Code），4 大模板：首问生成 / 报告生成 / 智能追问 / 维度分析。

**看点**：
- **"单问题铁律"**：最高优先级规则——"每次回复只能包含一个问题"，附正反示例；配合程序侧**问号计数自检**，多问即打回；
- **"禁止提前铺垫下一题"**：追问阶段不得暗示、铺垫下一话题；
- **深度追问引导**：明确要求追"具体场景"而非抽象概念、追"亲身经历"而非泛泛而谈、追"个人真实想法"而非官方回答；
- 9 种应对策略的完整定义（认真回答 / 敷衍回答 / 困惑不理解 / 拒绝不想答 / 不满情绪激动 / 要求结束 / 要求跳过 / 质疑测试边界 / 转移话题）；
- `analyzeWithDimensions` 模板定义了维度标注的输出结构（维度标签 + 情感 + 引用 + 涌现标签 + 访谈员评分）。

## 第三组 · 消息处理与状态持久化（可靠性根基）

### 7. `src/services/stream-message.service.ts` — 433 行

**职责**：钉钉消息处理管线——从消息抵达到驱动对话引擎的主流程。**本项目可靠性设计最集中的文件。**

**看点**：
- **消息去重**：LRU 缓存（容量 1000）记录已处理消息 ID，抵御重复投递；
- **用户级互斥锁**：同一用户的消息串行处理，从根源消除状态并发写冲突；
- **冷却守卫**：30 分钟无互动进入冷却，不主动打扰；
- **两阶段持久化**：LLM 调用前先落 `PROCESSING`，崩溃/宕机时消息不丢、状态可追溯；
- **版本冲突重试**：乐观锁冲突时自动重试；
- **超时 nudge**：访谈挂起 1 小时后温和提醒，最多 3 次；
- **死信告警**：处理失败落入死信记录，可发现、可追溯、可补救。

### 8. `src/services/stream-message-utils.ts` — 114 行

**职责**：消息处理纯工具函数集。

**看点**：
- **SSRF 防护**：Webhook 目标域名白名单（仅钉钉官方域名），拒绝任何越权外呼；
- 把可独立测试的纯函数从 434 行主服务中拆出，主服务保持流程清晰。

### 9. `src/repositories/interview-state.repository.ts` — 303 行

**职责**：访谈状态持久化——**乐观锁 + 增量写入**的数据层核心。

**看点**：
- `StatePersistenceError` 错误分类：VERSION_CONFLICT（版本冲突）/ TRANSACTION_ERROR（事务错误）/ NOT_FOUND（记录不存在）——让上层按错误类别做出不同处置（重试/告警/忽略），而非笼统 try-catch；
- **乐观锁校验**：写入时校验 `version` 与加载时的 `originalVersion` 一致才提交；`MAX_RETRIES = 3`；
- **增量写入**：`saveFullState()` 仅对新消息/回答做批量插入（`createMany`），不重写全量历史——避免长事务与写放大；
- 配套 `interview-state-mapper.ts`（57 行）做领域对象 ↔ 数据行映射，持久化细节不泄漏进业务层。

## 第四组 · 分析管线（对话 → 洞察）

### 10. `src/services/analysis.service.ts` — 345 行

**职责**：分析管线编排——访谈完结后自动执行的分析总调度。

**看点**：
- `buildQuestionMap` 构建问答映射（把消息流还原为"问题 → 回答"结构，含追问层级的归属）；
- **幂等设计**：重新分析先删除旧报告再生成，重跑不产生重复数据；
- `createBatchReportIfEligible` 使用 **discriminated union** 返回类型（"可聚合/不可聚合 + 原因"），把业务前置条件编码进类型系统；
- 维度分析链路中对接 PII 匿名化，原文引用不落隐私数据。

### 11. `src/services/report.service.ts` — 278 行

**职责**：报告生成与解析。

**看点**：
- 双轨生成：通用报告（`generateReport`）+ 维度报告（`generateReportWithDimensions`，temperature 0.1 保证可复现）；
- **解析容错三重设计**：
  1. 同时兼容 Markdown 标题与纯文本冒号两种 LLM 输出格式；
  2. 解析出关键发现 / 情感 / 行动建议的结构化字段（关键发现引用上限 5 条）；
  3. 解析失败或 LLM 返回空内容时，降级为 `createFallbackReport()` 兜底报告（保留原始问答记录）——**报告永不缺失**；
- 报告落盘 Markdown，文件名带时间戳。

### 12. `src/services/llm-clustering.ts` — 114 行

**职责**：LLM 主题聚类——把一批访谈归纳为子主题与涌现议题。

**看点**：
- 自动归纳 3-8 个子主题（temperature 0.1 低温度采样保证结果稳定可复现）；
- 提炼 Top 5 涌现议题并分级紧迫度——让"读 50 份访谈"变成"读 1 页结论"。

### 13. `src/services/batch-aggregation.service.ts` — 151 行

**职责**：批量聚合引擎——多份访谈的统计与整合。

**看点**：
- **Checkpoint 断点续跑**：任务中途失败可从中断处继续；
- **并发限流**：p-limit 控制 LLM 调用并发，保护 API 配额；
- **超时保护**：单批 5 分钟超时上限，挂起任务不占用资源；
- `computeDimensionStats` 维度的提及率与情感分布统计。

**看点**：

**职责**：通用重试工具 `withRetry()`。

**看点**：

- 62 行、零依赖，被报告生成、维度分析、LLM 调用等多处复用。

### 19. `src/utils/pii-anonymizer.ts` — 12 行

**职责**：PII 匿名化（**全项目最小的核心文件，13 行**）。

**看点**：
- 手机号 → `138****1234`、邮箱 → `[邮箱]`、人名 → `[匿名用户]`；
- 在分析链路（尤其原文引用）进入报告前做匿名化——隐私保护的最小侵入实现；
- 13 行代码说明一件事：**好的抽象让复杂需求变成小文件**。
