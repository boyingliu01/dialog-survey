# Contributing

## Commit messages

This project enforces [Conventional Commits](https://www.conventionalcommits.org/).

```
<type>(<optional scope>): <description>

[optional body]

[optional footer(s)]
```

Accepted types: `build`, `chore`, `ci`, `docs`, `feat`, `fix`, `perf`, `refactor`,
`revert`, `style`, `test`.

```bash
feat(admin): add template usage chart
fix: stop dropping the last dialog turn on retry
chore(deps): bump fastify to 5.6.1
docs: explain the PGlite test setup
```

### Where it is enforced

**CI is the enforcement point of record.** Every pull request runs the
`Commit Lint (Conventional Commits)` job in `.github/workflows/pr.yml`. Because
this repository squash-merges, the **PR title becomes the final commit message on
master**, so that title is what the blocking check validates. Commits inside the
branch are linted too, but only advisorily — they are discarded at merge time.

A separate `Revert`, `Merge`, `chore(release):`, `Bump ` and `chore(deps)` prefix
is tolerated for messages generated by git or by automation.

## Optional local hook (opt-in, NOT installed by default)

You can lint your commit message locally, before pushing:

```bash
bash scripts/install-git-hooks.sh
```

To undo it:

```bash
bash scripts/install-git-hooks.sh --uninstall
```

### ⚠️ Read this before installing

**While this hook is installed, this repository's global xp-gate gate chain does
not run.**

git reads hooks from exactly one directory: `core.hooksPath`. The installer points
`core.hooksPath` at this repository's `githooks/` directory. On a machine where
xp-gate wired its gates globally (`core.hooksPath=~/.config/xp-gate/hooks`), that
value is inherited by every repository — so overriding it locally means the
pre-commit and pre-push gates stop firing **for this repository only**.

That is why the hook is opt-in and nothing installs it for you. The trade is
explicit: you get a fast local conventional-commit check, and you lose the global
gate chain until you uninstall.

The uninstall restores the previous `core.hooksPath` exactly:

| State before install | Value restored by `--uninstall` |
|---|---|
| `core.hooksPath` unset | unset again (the inherited global value shows through) |
| `core.hooksPath` = `/some/path` | `/some/path` |

The pre-install value is recorded in `.git/xp-gate-uninstall-record` on first
install and is never overwritten by a repeat install. If `core.hooksPath` changed
since installation, `--uninstall` refuses to guess and exits non-zero; pass
`--force` to restore the recorded value anyway (the overwritten value is printed).
Only the repository's own config is ever written — global config is never touched.

## Checks to run before pushing

```bash
npm run type-check   # tsc --noEmit
npm run check        # biome
npm run test         # vitest
```

If a gate ever blocks a commit for a type or lint error that you cannot reproduce,
re-run the failing command directly first: some gates report a pipeline's exit
status rather than the tool's.
